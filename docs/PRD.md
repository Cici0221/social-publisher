# 社媒一键发布平台 PRD

Nov 24, 2026 · @Xinke Liu

## 1. 背景与目标

宣传部在一个页面里上传素材、写文案、勾选平台，点一次按钮就把内容发到 14 个社媒平台。现在的做法是逐个平台登录、上传、粘贴文案，同一条内容要重复操作十几遍，容易漏发和发错版本。

### 目标

- 一条内容从写完到提交全部平台，操作时间不超过 3 分钟（建议值，待确认）。
- 每个平台的发布结果在同一页可见：成功、失败及原因、帖子链接。
- 所有发布有记录可查：谁在什么时间往哪个账号发了什么。

### 本期不做

- 评论、私信的统一回复。
- 数据分析看板（阅读量、涨粉等）。
- 广告投放。
- AI 自动生成文案或视频。
- 模拟登录、RPA 等绕过平台限制的发布方式：违反平台规则，公司官方账号有被封风险。

## 2. 用户与角色

使用者是公司宣传部员工，分三种角色；审核环节可由管理员整体开启或关闭。

| 角色 | 谁 | 能做什么 |
| --- | --- | --- |
| 管理员 | 部门负责人或 IT | 绑定和解绑社媒账号、管理成员和角色、开关审核流程、查看全部记录 |
| 编辑 | 宣传部员工 | 上传素材、写文案、选平台、提交发布（审核开启时为提交审核）、查看自己的记录 |
| 审核人 | 部门负责人或指定同事 | 查看待审内容、通过或退回并填写意见 |

## 3. 平台范围与分期

14 个平台在同一个版本里全部开发，按接入方式分三类：A 类 8 个海外平台走官方接口直发；B 类 4 个国内平台走官方接口直发，账号已有企业认证，待发布权限审批通过后启用；C 类 2 个平台没有可用的发布接口，做半自动发布。

| 类别 | 平台 | 接入方式 | 前置条件 |
| --- | --- | --- | --- |
| A | YouTube | 官方接口直发 | Google 开发者项目，频道授权 |
| A | Facebook | 官方接口直发 | Meta 开发者应用，公共主页授权 |
| A | Instagram | 官方接口直发 | 企业号或创作者号，并关联 Facebook 主页 |
| A | Threads | 官方接口直发 | Meta 开发者应用，账号授权 |
| A | LinkedIn | 官方接口直发 | LinkedIn 开发者应用，公司主页管理员授权 |
| A | Bluesky | 官方接口直发 | 账号的应用专用密码 |
| A | X | 官方接口直发，按量付费 | 开发者账号并充值；每帖 0.015 美元，带链接 0.20 美元 |
| A | TikTok | 官方接口直发 | 开发者应用须通过官方审核，否则内容仅私密可见 |
| B | 抖音 | 官方接口直发 | 已有企业认证；申请“代替用户发布内容到抖音”能力 |
| B | 微博 | 官方接口直发 | 已有企业认证；申请发布权限（待核实） |
| B | 快手 | 官方接口直发 | 已有企业认证；申请发布权限（待核实） |
| B | 哔哩哔哩 | 官方接口直发 | 已有企业认证；申请投稿权限（待核实） |
| C | 小红书 | 半自动 | 未查到公开的发布接口；人工在官方创作者后台确认发布 |
| C | 微信视频号 | 半自动 | 未查到面向第三方的发布接口；人工在视频号助手确认发布 |

标“待核实”的条目和 A 类各平台的前置条件来自既有知识，开发前须按各平台官方文档逐项核对。各平台的应用审核和权限申请周期不可控，开发启动当天即提交；上线时权限还没批下来的平台，先按半自动方式运行。

## 4. 核心流程

一条内容从创建到发布完成走以下 7 步；半自动平台在第 6 步改为人工确认。

1. 新建内容：编辑点击“新建发布”。
2. 上传素材：拖入图片或视频，或从素材库选取。
3. 写文案：填写通用标题、正文、话题标签。
4. 勾选平台：勾选要发布的平台和账号；系统即时校验各平台的字数、素材格式、时长，不合规的平台标红并提示原因。
5. 按平台微调（可选）：对单个平台改写文案、换封面、调整标签，不影响其他平台。
6. 发布：选择立即发布或定时发布，点击“一键发布”。审核开启时先进入待审，审核通过后自动执行。
   - 直发平台：后台逐个调用接口，页面实时显示每个平台的进度。
   - 半自动平台：生成该平台的文案和素材包，提示编辑一键复制并跳转官方后台完成发布，回来后标记“已发布”并贴回链接。
7. 查看结果：每个平台显示成功（附帖子链接）或失败（附原因），失败可单独重试。

## 5. 功能需求

共 8 个模块、30 条需求；P0 和 P1 都在首个版本交付，P2 为后续迭代。审核流（5.5）随首个版本交付，默认关闭，管理员可随时开启。

### 5.1 素材库

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| M-1 | 支持拖拽和批量上传图片（JPG、PNG、GIF）和视频（MP4、MOV），大文件分片上传、断点续传 | P0 |
| M-2 | 上传后显示缩略图、尺寸、时长、文件大小 | P0 |
| M-3 | 素材可按文件夹和标签整理，可按名称、标签、上传人、日期搜索 | P1 |
| M-4 | 同一素材可被多条内容复用，删除素材前提示被哪些内容引用 | P1 |

### 5.2 内容编辑

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| C-1 | 通用内容包含标题、正文、话题标签、素材、视频封面 | P0 |
| C-2 | 每个已勾选平台有独立页签，默认继承通用内容，可单独改写；改写后不再随通用内容变化，并有“恢复通用”按钮 | P0 |
| C-3 | 实时显示各平台字数与上限 | P0 |
| C-4 | 支持多语言版本（中文、英文、日文、越南语），每个平台账号可指定使用哪个语言版本 | P1 |
| C-5 | 草稿自动保存，可从草稿箱继续编辑 | P0 |

### 5.3 平台选择与校验

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| S-1 | 平台以复选框列出，按“国内”“海外”分组，支持全选；未绑定账号或授权过期的平台置灰并提示 | P0 |
| S-2 | 同一平台绑定多个账号时可多选账号 | P1 |

| S-4 | 提交前按第 6 节规则校验每个平台；不通过的平台标红并列出原因，可选择修改或跳过该平台 | P0 |

| 编号 | 需求 | 优先级 |
| --- | --- | --- |

| P-2 | 进度页实时显示每个平台的状态：排队中、上传中、平台审核中、成功、失败 | P0 |

## 6. 各平台内容规则与适配

每个平台支持的内容形式和文案上限不同，系统把这些规则做成可配置项，提交前自动校验。下表是初稿，数值来自既有知识，开发前须按各平台官方文档核对；空缺项在核对时补全。

| 平台 | 支持形式 | 文案上限（初稿） | 适配要点 |
| --- | --- | --- | --- |
| X | 文字、图片、视频 | 280 字符 | 带链接的帖子费用高，提交前提示 |
| Bluesky | 文字、图片、视频 | 300 字符 | 链接和标签需单独标注位置 |
| Threads | 文字、图片、视频 | 500 字符 | |
| Facebook | 文字、图片、视频 | 待核对 | 发到公共主页 |
| Instagram | 图片、视频（必须有素材） | 2200 字符 | 纯文字不可发；正文链接不可点击 |
| LinkedIn | 文字、图片、视频 | 3000 字符 | 发到公司主页 |
| YouTube | 视频（必须有视频） | 标题 100、描述 5000 字符 | 需选择公开范围；竖版短视频按 Shorts 处理 |
| TikTok | 视频、图片 | 2200 字符 | 发布前须展示官方要求的确认项（可见范围、是否允许评论等） |
| 抖音 | 视频、图文 | 待核对 | 竖版 9:16 为主 |
| 快手 | 视频 | 待核对 | 竖版 9:16 为主 |
| 微博 | 文字、图片、视频 | 待核对 | |
| 哔哩哔哩 | 视频（必须有视频） | 待核对 | 须选分区和标签，横版 16:9 为主 |
| 小红书 | 图文、视频（必须有素材） | 标题 20 字、正文 1000 字 | 半自动；竖版 3:4 为主 |
| 微信视频号 | 视频、图片 | 待核对 | 半自动 |

### 统一的适配逻辑

- 素材与平台不匹配时（如只有图片却勾了 YouTube），该平台标红并说明原因，不阻塞其他平台。
- 文案超长时提示超出字数，由编辑手动缩写，系统不自动截断。
- 视频比例与平台推荐比例不符时给出提醒，不强制拦截。

## 7. 非功能需求

安全是第一优先：系统持有公司全部官方账号的发布权限，泄露等于所有账号同时失守。

| 类别 | 要求 |
| --- | --- |
| 安全 | 各平台授权令牌加密存储，前端和日志中不出现明文；登录接入公司统一账号或强制二次验证；所有发布、授权、权限变更写入不可删除的操作日志 |
| 权限 | 按第 2 节角色控制；编辑无法查看或导出授权令牌 |
| 性能 | 支持单个视频文件 2 GB（建议值）；点击发布后 2 秒内进入进度页，实际上传在后台执行，关闭页面不中断 |
| 可靠性 | 单个平台失败不影响其他平台；定时任务在服务重启后不丢失；同一内容对同一账号不重复发出 |
| 网络 | 服务器须同时能稳定访问国内和海外平台的接口，部署方案见第 8 节 |
| 合规 | 只使用各平台官方开放接口，遵守其开发者协议和调用频率限制；素材和文案的版权、广告合规由发布人和审核人负责 |
| 兼容 | 桌面端 Chrome、Edge、Safari 最新两个版本；界面语言为简体中文 |

## 8. 技术方案建议

核心设计是“统一发布层 + 平台适配器”：业务逻辑只写一次，每个平台一个独立适配器，平台接口变更或新增平台时只改对应适配器。以下为建议，最终由开发团队决定。

| 组成 | 职责 |
| --- | --- |
| Web 前端 | 素材上传、内容编辑、平台勾选、进度与记录页面 |
| 业务服务 | 账号与权限、内容与草稿、审核流、校验规则、发布任务拆分 |
| 任务队列与调度 | 每个“内容 × 平台账号”为一个独立任务，支持定时、重试、幂等 |
| 平台适配器（14 个） | 统一接口：授权、续期、校验、上传素材、发布、查询状态；半自动平台的适配器只生成素材包和跳转链接 |
| 对象存储 | 保存原始素材和缩略图，支持分片上传 |
| 数据库 | 用户、账号授权（加密）、内容、发布任务、操作日志 |

部署：国内平台接口需从境内访问，海外平台接口需从境外访问。建议主系统部署在一处，另一侧部署只负责调用平台接口的发布节点；素材跨境传输的合规要求需 IT 和法务确认。

自研与采购：市面上有现成的多平台发布工具和聚合发布接口，可覆盖大部分海外平台。立项前建议做一次对比：海外部分采购、国内部分自研，可能比全部自研更快。

## 9. 里程碑、验收与风险

由公司内部自行开发，14 个平台在一个版本里交付，不设试用阶段，做完直接交给宣传部；以“用真实账号发出真实内容”为验收标准。

| 阶段 | 内容 | 完成标准 |
| --- | --- | --- |
| 0 | 提交全部平台的开发者应用和发布权限申请（与开发并行） | 12 个直发平台的申请均已提交 |
| 1 | 搭建框架：登录与角色、素材库、内容编辑、任务队列、适配器统一接口，并接通第一个平台 | 一条内容能通过界面发到第一个平台，并显示结果 |
| 2 | 其余 11 个直发平台的适配器，定时发布、审核流、发布日历、多语言版本、平台组合 | 每个已获权限的平台用真实账号发布成功；失败能显示原因并重试 |
| 3 | 小红书、微信视频号半自动发布；发布记录与导出、通知 | 编辑从点击到在官方后台完成发布不超过 2 分钟（建议值） |
| 4 | 整体验收与交付 | 一条含视频的内容一次提交到全部 14 个平台：直发平台全部成功，半自动平台完成人工确认 |

### 上线后衡量指标（目标值待确认）

- 单条内容的平均发布操作时长。
- 直发平台的首次发布成功率。
- 宣传部通过本平台发布的内容占全部发布量的比例。

### 风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 国内平台发布权限申请被拒或周期长 | 对应平台上线时只能半自动 | 开发启动当天即提交申请；被拒的平台降级为半自动 |
| TikTok 应用审核未通过 | 内容仅私密可见 | 按官方界面规范实现发布页，预留审核整改时间 |
| 平台接口或收费规则变更 | 某平台发布中断或成本上升 | 适配器隔离；监控各平台失败率并告警；X 按月统计费用 |
| 授权令牌泄露 | 全部官方账号被盗发 | 加密存储、最小权限、操作日志、异常发布告警 |
| 误发或发错版本 | 品牌事故 | 审核流、提交前的确认摘要页 |

### 待确认事项

已确认：国内平台账号均有企业认证；由公司内部自行开发；全部平台一个版本交付；审核流随首个版本交付、默认关闭。

- 每个平台有几个账号，是否按市场（日本、越南、国内）分账号？
- 使用人数和预计每日发布条数？
- 期望上线时间？
- 服务器部署位置，以及素材跨境传输的合规要求？

以下两项来自网页搜索结果的摘要，未打开原页逐字核对；其余平台信息来自既有知识。

- X API 定价：按量付费及单价。
- TikTok Content Posting API：未审核应用的内容仅私密可见。
